# 学生100人運動会 SNS集客 — 下書きと分析の運用キット

**目的**: 10/24(土)の「学生100人運動会」の参加者を100人にする(2026-10-05時点: 40人)。
**主KPI**: SNS経由のフォーム回答数。再生数・いいね数は手段の指標で、成功の判断基準にしない。

**やらないこと**: 自動投稿、API連携、自動改善ループ。投稿、数字の貼り付け、最終判断はげんが行う。
SNSだけで60人を取る設計にはしない。SNSの役割は、新規層への認知と、運営の信頼の可視化。

## ファイル

| ファイル | 役割 |
|---|---|
| `00_fixed_facts.md` | 固定情報、書いてよい/まだ書かない項目、承認ルール |
| `01_voice.md` | トーン定義、げんの修正差分ログ |
| `02_setup_today.md` | アカウント作成、プロフィール文、計測、フォーム設問、3日間の投稿配分 |
| `prompts/daily_draft.md` | **下書き生成テンプレート** |
| `prompts/daily_report.md` | **数字を貼ると分析を返す型** |
| `decision_rules.md` | 10/8の判定ルール(判断不能の条件を含む) |
| `log/posts.csv` | 投稿ログ(【SNS・型】タグ付き、数字は24〜48時間後に追記) |
| `log/daily_numbers.csv` | 日次の数字(フォーム回答、SNS別) |
| `log/recontact.csv` | 8/14に申し込んだ131人への再連絡の状況(**人数のみ。名前は書かない**) |

## 毎日の流れ(1日3時間の配分案)

| 時間 | 内容 |
|---|---|
| 10分 | 前日の数字を `prompts/daily_report.md` で貼る → ①累計と差 ②傾向 ③明日変える要素 |
| 15分 | 当日分の下書きを `prompts/daily_draft.md` で依頼 → 確認(日時・場所・料金に触れる投稿は必ず確認) |
| 90分 | 撮影・編集(TikTok動画) |
| 20分 | 手動投稿 |
| 10分 | `log/` に記入(posts.csv、daily_numbers.csv、recontact.csv) |
| 約35分 | **人的導線** |

### 人的導線(SNSより先に効く可能性が高い)
残り60人÷18日は、1日あたり約3.3人。SNS経由の見込み(5〜15人)だけでは足りない。

- **8/14に申し込んだ131人**への再連絡(声かけ済み)。返信状況を `log/recontact.csv` に人数で記録する。
  - 未返信・検討中の人に、「日程以外で迷っている点があれば教えてほしい」と一言聞く。**日程NG以外の理由は、型Bの材料になる**(マーケットイン)。
- ペアを連れてきてもらう声かけ(10/8に最初の反応を確認)。
- サークル・友人網への連絡。

## 毎日の確認(承認ポイント)

1. 日時・場所・料金に触れる投稿は、投稿前にげんが確認する。
2. 運営メンバーの名前・大学・顔を含む投稿は、本人の許可を確認する。
3. `00_fixed_facts.md` の「まだ書かない」に触れる内容は、確認が出るまで投稿しない。

## 日程(今日 10/6 時点)

- 10/6〜10/8: 3日間の手動テスト(各SNSで型A・B・Cを1〜2本)
- 10/8(夜): `decision_rules.md` で判定
- 10/17頃: 「まだ空いている人へ」の再告知を入れる(予定)
- 10/23: 申込締切 / 10/24: 開催

## 前提と限界

- フォームの「何で知りましたか」は自己申告。友人経由でSNSを見て申し込んだ人は「友人・知人の紹介」に入るので、SNS経由は過小に出る。
- GoogleフォームはUTMを記録しない(詳細は `02_setup_today.md`)。
- 3日分のデータでは統計的な判断はできない。判断不能のときは、そう書く。
